#### Interfaces and security

- `GET/POST /api/document-records` list and create records via the application use case.
- `GET /api/document-records/{recordId}` returns a vault-scoped public workspace.
- A short-lived upload ticket and Vercel Blob client token are issued only after
  Clerk authentication and record ownership checks; upload is private and limited
  to the contract MIME types and 10 MiB per asset.
- The authenticated finalize request re-reads the private Blob and checks ticket
  path, owner scope, actual content type, byte limit and file signature before
  calling the application use case. Each request handles one asset; the browser
  uploads sequentially to preserve page order and never sends file bytes through
  a Vercel Function.
- Asset preview is served by an authenticated `no-store` route. Public records,
  client state and logs never contain Blob URLs, `blobPath` or SHA-256.
- User scope is derived from Clerk identity and the personal-vault resolver;
  client-supplied `actorId`, `vaultId` or arbitrary storage paths are rejected.
- Web transport calls application use cases and never the DB repository directly.

#### Acceptance

- Home and Documents show all eight type cards and localized record/status summaries.
- Previously uploaded generic PDFs remain visible and downloadable in a separate
  unclassified-files list; they are never silently assigned a document type.
- If typed-record storage is unavailable, the catalog remains visible but the
  typed upload control fails closed with an explanation.
- Selecting a type opens an accessible workspace with versioned type fields,
  multiple JPEG/PNG/PDF pages, local preview, reorder/remove controls and clear
  5-page/10-MiB limits.
- Saving creates one typed record and appends assets in visible order; retrying a
  partially completed upload does not duplicate identical pages.
- Until a real OCR provider passes Task 3 gates, typed fields remain visibly
  unrecognized; no extracted values or confidence are fabricated.
- Loading, empty, upload progress, partial failure and success are localized RU/EN.
- Light/dark/system, keyboard/touch, focus, reduced motion and axe checks pass.
- OCR is explicitly shown as unavailable until a provider passes Task 3 gates;
  no manual form or fixture is presented as live OCR.
- API and asset routes are owner/vault scoped, return `no-store`, and never expose
  provider/storage details or a private URL.

## Task 4 — provider selection and production smoke

Provider choice is made after benchmark, not by model preference. Verify with
real private assets in a signed-in session, then run `npm run check`, security
review, audit/redaction checks, migration verification and production smoke.

## Stop conditions

- no provisioned OCR provider or missing approved secret;
- provider does not support required language/document type at target quality;
- any path would make raw image/OCR payload public or auto-confirm fields;
- benchmark sample contains real PII without explicit user-approved handling.
