# Соглашение о коммитах

Каждый коммит содержит один логический результат и самостоятельно проходит
применимые проверки. Заголовок соответствует Conventional Commits:

```text
<type>(<scope>): <описание на русском языке>
```

## Type

- `feat` — новое пользовательское или публичное поведение;
- `fix` — исправление дефекта;
- `docs` — только документация;
- `refactor` — структура без изменения поведения;
- `test` — тесты без production behavior change;
- `perf` — измеримое улучшение производительности;
- `build` — сборка, dependencies или packaging;
- `ci` — automation/CI;
- `chore` — обслуживающее изменение вне предыдущих типов;
- `revert` — откат конкретного коммита.

## Scope

Scope необязателен. Используй короткое имя модуля латиницей в kebab-case:
`documents`, `finance`, `timeline`, `notifications`, `integrations`, `ai`, `mcp`,
`cli`, `ui`, `db`, `auth`, `infra`.

Не используй имя файла как scope, если файл не является стабильной областью
ответственности.

## Русское описание

- Начинай со строчной буквы.
- Называй завершённое изменение конкретным глаголом.
- Не ставь точку в конце.
- Держи заголовок не длиннее 72 символов.
- Причину, ограничения и migration notes выноси в тело.

Примеры:

```text
docs(ai): внедрить правила работы AI-агентов
feat(documents): добавить приватную загрузку PDF
fix(finance): исключить дубли при повторном импорте CSV
perf(ui): сократить гидратацию панели операций
test(mcp): проверить запрет межтенантного чтения
```

## Breaking changes

Добавь `!` после type/scope и footer на русском:

```text
refactor(mcp)!: унифицировать контракты инструментов

BREAKING CHANGE: клиенты должны передавать vaultId в каждом вызове
```

## Тело и footers

Тело объясняет «почему» и важные trade-offs, а не повторяет diff. Ссылки на
задачи и co-authorship размещаются отдельными footer-строками.

## Перед коммитом

1. Проверь, что staged diff содержит только один task packet.
2. Выполни `git diff --cached --check` и прочитай `git diff --cached`.
3. Запусти completion gate.
4. Проверь тип, scope, русский заголовок и длину.

Заголовки вроде `update`, `fix stuff`, `правки`, `misc` и коммиты «заодно» не
принимаются: раздели результат или сформулируй его точно.
